# QwickSite Production SEO — DevOps Configuration and Release Checklist

Use this document to configure and verify the QwickSite landing website in production.

## Target production architecture

- **Application:** `qwicksite-landing`
- **Framework:** Next.js 15
- **Canonical host:** `https://www.qwicksite.com`
- **Supported locales:** English (`/en`) and Arabic (`/ar`)
- **SEO verification command:** `npm run seo:verify`

If the business chooses the non-`www` domain instead, update `SITE_URL`, DNS, redirects, Search
Console, analytics, and every acceptance check in this document together. Do not operate with
different canonical hosts at different layers.

## Current production baseline

The following issues were observed before this handoff:

- `https://www.qwicksite.com/robots.txt` returned `404`.
- `https://www.qwicksite.com/sitemap.xml` returned `404`.
- Alternate-domain and HTTP redirects returned `307` or `308`, not the required `301`.
- `/` redirected to `/en` with `307`.
- The expected `/images/*` browser-cache policy was missing.

The release is not SEO-complete until the final checklist at the end of this document passes.

## 1. Deploy the SEO-enabled application

Deploy the approved commit from `ehab/feat/add-seo` or the branch into which it is merged.

Use the project lockfile and production build:

```bash
npm ci
npm run build
npm run start
```

The production build must expose these application routes:

```text
/robots.txt
/sitemap.xml
/en
/ar
/en/pricing
/ar/pricing
/en/features
/ar/features
```

The SEO pages and remaining localized routes are generated by the same Next.js application.

Do not deploy `.next` from a different commit, serve a legacy static export, or route
`robots.txt`/`sitemap.xml` to an old application.

---

## 2. Configure production environment variables

Set the following values in the production hosting platform before building:

```text
SITE_URL=https://www.qwicksite.com

GOOGLE_SITE_VERIFICATION=<google-verification-token>
NEXT_PUBLIC_GA_MEASUREMENT_ID=G-XXXXXXXXXX
NEXT_PUBLIC_CLARITY_PROJECT_ID=<clarity-project-id>

QWICKSITE_FOUNDING_DATE=YYYY-MM-DD
QWICKSITE_FOUNDER_NAME=<approved-public-founder-name>
QWICKSITE_FOUNDER_URL=https://<approved-public-founder-profile>
QWICKSITE_SOCIAL_URLS=https://<official-social-profile-1>,https://<official-social-profile-2>
```

Requirements:

- `SITE_URL` must contain one HTTPS origin with no path or trailing slash.
- `NEXT_PUBLIC_*` values must be available during `npm run build`.
- Founder, founding date, profile, and social URLs must be approved public facts.
- Social URLs must use HTTPS and must not contain placeholders.
- Do not put private Google credentials, service-account keys, API secrets, or OAuth tokens in
  `NEXT_PUBLIC_*`.
- Redeploy the application after changing any build-time environment variable.

## 3. DNS, TLS, and canonical-domain redirects

Provision DNS and valid TLS certificates for:

```text
qwicksite.com
www.qwicksite.com
```

Configure these one-hop redirects at the CDN, load balancer, or hosting edge:

```text
http://qwicksite.com/*      → https://www.qwicksite.com/*
https://qwicksite.com/*     → https://www.qwicksite.com/*
http://www.qwicksite.com/*  → https://www.qwicksite.com/*
```

Redirect requirements:

- Return HTTP `301`.
- Preserve the full pathname.
- Preserve query parameters.
- Do not create redirect chains.
- Do not redirect the canonical HTTPS host to itself.
- The final canonical URL must return `200`.

Verification examples:

```bash
curl -I http://qwicksite.com/en
curl -I https://qwicksite.com/en
curl -I http://www.qwicksite.com/en
curl -I https://www.qwicksite.com/en
```

Expected:

- The first three requests return one `301` to `https://www.qwicksite.com/en`.
- The final request returns `200`.

The application also normalizes locale, trailing-slash, demo, and first-pagination aliases. Ensure
the platform does not replace application `301` responses with `307` or `308`.

---

## 4. Route `robots.txt` and `sitemap.xml` to Next.js

The proxy/CDN must pass these paths to the deployed Next.js application:

```text
/robots.txt
/sitemap.xml
/en/*
/ar/*
```

Remove conflicting static-file rules, rewrites, redirects, cached 404 responses, or legacy
application mappings.

After deployment:

```bash
curl -I https://www.qwicksite.com/robots.txt
curl -I https://www.qwicksite.com/sitemap.xml
```

Both responses must return `200`.

`robots.txt` must:

- Allow public pages to be crawled.
- Disallow only `/api/`.
- Reference `https://www.qwicksite.com/sitemap.xml`.
- Declare `https://www.qwicksite.com` as the host.

The sitemap must contain only canonical HTTPS URLs with no query strings or fragments. Every sitemap
URL must return `200` and declare itself as its canonical.

---

## 5. Compression

Enable both:

- Brotli when the request contains `Accept-Encoding: br`.
- Gzip when the request contains `Accept-Encoding: gzip`.

Avoid double compression between the Next.js origin and CDN.

Verify:

```bash
curl -sSI -H 'Accept-Encoding: br' https://www.qwicksite.com/en
curl -sSI -H 'Accept-Encoding: gzip' https://www.qwicksite.com/en
```

Expected response headers:

```text
Content-Encoding: br
Content-Encoding: gzip
```

---

## 6. Browser caching

Use these policies unless the hosting platform provides stricter equivalent defaults:

### Hashed Next.js assets

```text
Path: /_next/static/*
Cache-Control: public, max-age=31536000, immutable
```

### Public marketing images

```text
Path: /images/*
Cache-Control: public, max-age=86400, stale-while-revalidate=604800
```

### HTML, robots, and sitemap

Use safe CDN revalidation or:

```text
Cache-Control: no-cache
```

Do not apply a one-year immutable cache to HTML, `robots.txt`, `sitemap.xml`, or mutable same-name
public files.

Verify:

```bash
curl -sSI https://www.qwicksite.com/images/qwicksite-ai-website-builder-dashboard.webp
curl -sSI https://www.qwicksite.com/robots.txt
curl -sSI https://www.qwicksite.com/sitemap.xml
```

Purge old cached 301/307/308/404 responses after deploying the corrected configuration.

---

## 7. Indexability and crawler headers

For every canonical page in the sitemap:

- Do not inject `X-Robots-Tag: noindex`.
- Do not inject a global `<meta name="robots" content="noindex">`.
- Do not block `/en/*` or `/ar/*` through the WAF or CDN.
- Do not require authentication, cookies, geographic access, or a browser challenge for crawlers.

Checkout pages intentionally use page-level `noindex, follow` and are excluded from the sitemap.

Verify a public page:

```bash
curl -sSI https://www.qwicksite.com/en | grep -i x-robots-tag
```

The command should produce no `noindex` header.

## 8. Google Search Console

The SEO or DevOps owner must:

1. Verify the `qwicksite.com` Domain property through DNS.
2. Keep `GOOGLE_SITE_VERIFICATION` configured as the HTML-verification fallback.
3. Submit:

   ```text
   https://www.qwicksite.com/sitemap.xml
   ```

4. Confirm that Google successfully reads the sitemap.
5. Use URL Inspection → Test Live URL → Request Indexing for both locales of:

   ```text
   Homepage: /en and /ar
   Pricing:  /en/pricing and /ar/pricing
   Features: /en/features and /ar/features
   About:    /en/about and /ar/about
   Contact:  /en/contact and /ar/contact
   Blog:     /en/blog and /ar/blog
   ```

6. Inspect and request indexing for every new article after publication.
7. Recheck indexing after 24 hours and 72 hours.
8. Review weekly:
   - Page indexing
   - Sitemap coverage
   - Crawl statistics and crawl errors
   - Core Web Vitals
   - HTTPS
   - Manual actions
   - Security issues
   - Canonical and `noindex` exclusions

Do not use Google's specialized Indexing API for ordinary blog articles.

## 11. Core Web Vitals and performance acceptance

Run mobile and desktop PageSpeed Insights for:

- English and Arabic homepages
- Pricing
- Features
- Blog
- One long SEO content page
- Every new article template

Field acceptance must be measured at the 75th percentile for mobile and desktop:

```text
LCP < 2.5 seconds
CLS < 0.1
INP < 200 milliseconds
```

Record lab results after deployment. Final field sign-off requires representative GA4/CrUX/Search
Console data; it cannot be inferred from a successful build alone.

QwickSite AI

Arabic Website Builder

Redirect a 404 only when a genuine replacement exists. Fix internal broken links at their source.

## 13. Automated post-deployment verification

From the deployed revision, run:

```bash
SITE_URL=https://www.qwicksite.com npm run seo:verify
```

The command checks:

- `robots.txt` and sitemap availability
- All required English and Arabic SEO pages
- HTTP `200` on canonical sitemap URLs
- Canonical URLs
- Accidental meta/header `noindex`
- Metadata and H1 presence
- Page-level and entity structured data
- Founder ↔ Organization linking
- GA4, Clarity, and Search Console output
- UTM canonical stripping
- Checkout `noindex`
- Unknown-route `404`
- Alias, HTTP, and alternate-host `301` redirects
- Brotli and Gzip
- Image caching

Do not approve the deployment while this command reports failures.

## 14. Structured-data constraints

- SoftwareApplication offers must match the visible pricing plans.
- Do not relabel visible `Launch`, `Growth`, and `Expansion` plans only in JSON-LD.
- Review/AggregateRating must remain absent until genuine visible reviews have documented author,
  text, rating, scale, date, and provenance.
- SearchAction must remain absent until QwickSite provides a real on-site search-results URL.
- Do not invent founder, founding-date, social-profile, plan, or review data.
